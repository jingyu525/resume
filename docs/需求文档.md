# Résumé Studio · 简历工作室 — 产品需求文档（PRD）

> 本文档是产品的**需求唯一事实来源（SSOT）**，描述"产品应当做什么"，不绑定任何具体技术实现方案。
> 品牌话术口径以品牌策略文档为准。文档标注 `【现状】` 表示当前已具备，标注 `【目标】` 表示重建时需保证的能力。

---

## 一、产品概述 · Overview

### 1.1 一句话定位
本地优先、所见即所得（WYSIWYG）的简历排版工作室——让没有设计基础的人，也能把简历做成"苹果专业文档级"的作品。

### 1.2 品类
简历编辑器 / Résumé Editor。**不是**模板商城、**不是** AI 代写、**不是** Word 替代品。

### 1.3 差异化锚点
把"专业排版能力"从设计师手里下放给普通人，且**全程不离开用户浏览器、不碰用户数据**。

### 1.4 核心价值主张
| 维度 | 主张 | 收益 |
|---|---|---|
| 主价值 | 所见即所得 + A4 精确分页，用户只管写内容 | 写完即成品，导出 PDF 不丢版式 |
| 次级价值 | 设计级排版、正文字体跨设备一致 | 普通人也能产出"作品级"质感 |
| 信任价值 | 本地优先、零外部 AI、数据只留浏览器 | 隐私可控，不用把简历交给聊天机器人 |

### 1.5 解决的核心痛点（三大旧范式）
1. **Word**：手调排版、跨设备字体错位、导出 PDF 常丢版式。
2. **Markdown**：排版力弱、A4 分页/边距不可控、导出 PDF 丑。
3. **纯 AI 代写**：内容不可控、调试要精通提示词、难稳定落版。

## 二、目标用户 · Users

通用定位，不限定单一群体；以下画像用于写文案时有具体对象。

| 画像 | 特征 | 痛点 | 产品侧重 |
|---|---|---|---|
| 求职新手 | 应届/转行，第一次认真做简历 | Word 调版崩溃、不懂排版 | 点哪改哪，零设计基础也能专业 |
| 职场进阶者 | 3–10 年经验 | Markdown 导出丑、想体现质感 | 作品级质感、字体一致 |
| 开发者 | 关注实现、爱看代码仓库 | 反感黑盒 SaaS、不愿上传数据 | 本地优先、开源、工程透明 |
| 设计敏感者 | 重视字体与版面 | 现有工具排版力弱 | A4 精确分页、导出即成品 PDF |

**跨群体共识诉求**：专业感、可控、不泄密、不折腾。

## 三、功能需求 · Functional Requirements

### FR-1 营销落地页【现状】
- 独立首页，与编辑器解耦。
- 顶部导航：品牌标识、语言切换、代码仓库链接、立即体验入口。
- Hero 区：双语主标语（"把简历做成一件作品 / Craft a résumé like a pro document"）、副标语、双 CTA、隐私徽标。
- 功能亮点区：6 个特性卡片，逐条对应核心优势。
- "为什么不是…"区：点名 Word / Markdown / 纯 AI 三类痛点。
- 编辑器截图展示区。
- 工程底座展示区（仅作信任背书，说明纯前端、本地优先、开源等理念）。
- 底部 CTA + 隐私承诺。
- **响应式**：移动端单列，桌面端多列网格。
- **深浅色**：跟随系统偏好自动切换。

### FR-2 简历编辑器（核心）【现状】
- 独立编辑器页面。
- **布局**：
  - 桌面：左侧编辑面板 + 右侧 A4 实时预览。
  - 移动端：底部 Tab 切换"编辑 / 预览"，默认进入预览。
- **顶栏**：品牌 + 撤销/重做 + 主色快捷（宽屏）+ 外观菜单 + 更多菜单 + 打印（最右，最终出口）。
- **左侧编辑面板结构**：
  1. 基本信息卡（姓名、职位、电话、邮箱、城市、微信、网站）。
  2. 动态章节列表，按顺序排列，每个章节可拖拽排序、可隐藏/显示、可改标题：
     - 自我评价（整块富文本）
     - 工作经历（多条目）
     - 项目经历（多条目）
     - 教育背景（多条目）
     - 专业技能（多分组）
  3. 每个经历类条目支持：新增 / 删除 / 上移 / 下移 / 拖拽排序；字段含主标题、副标题、起止时间、是否"至今"、描述（富文本）。
  4. 技能组支持：新增 / 删除 / 上移 / 下移；字段含分类名、条目列表。

### FR-3 就地编辑（Inline Editing）【现状】
- 简历正文（预览区）上的文字**可直接点击编辑**，所见即所得。
- 富文本描述支持选中文字后浮层操作：**加粗 / 强调色 / 还原格式**（仅 3 个感知级动作）。
- 用户粘贴的外部内容须自动清洗掉外部排版（字号/字体/背景等），仅保留语义与强调色；纯文本粘贴须保留分段结构。
- 编辑区与预览/打印**共用同一份处理过的富文本**，避免两份不一致。

### FR-4 内容组织【现状】
- 内容（写什么）与观感（长什么样）在概念上完全分离，互不影响。
- 内容字段支持多语言（见 FR-6）。
- 时间字段（起止日期、"至今"标记）与语言无关。
- 默认提供空白简历 + 纸面占位引导，而非预置他人内容；另提供"填充示例"动作供参考。

### FR-5 排版与外观（Appearance）【现状】
- 通过**四个直觉维度**调整观感（不直接暴露底层排版参数）：
  1. **主色**：精选若干专业色，避免选色压力。
  2. **版式**：单栏 / 侧栏双栏 两种。
  3. **气质**：若干档（如正式/柔和/活泼），用户选"感觉"而非直接选字体。
  4. **疏密**：一个滑块控制整体紧凑↔舒展（影响页边距、区块间距、行高、字号）。
- 提供"一键恢复默认观感"。
- 排版参数由系统将直觉轴翻译为具体版面数值。
- **设计原则：预设选感觉，微调改参数**（改动外观能力前请先回到本条）：
  1. 上层「模板」＝选感觉：内置五个预制主题，把主色 / 版式 / 气质 / 疏密打包成一个可整体挑选的结果。**预制的意义在于降低选择压力**——用户不必面对参数，因此模板区只提供"整体感觉"，不再往里加参数开关。
  2. 下层「微调」＝改参数：四个直觉维度留给"大方向喜欢、还想再调一点"的用户。两层互补，不互相替代。
  3. 模板以缩略图呈现，缩略图吃的是简历渲染的同一套 CSS 变量，因此"感觉"真实可见，而不是靠名字想象。

### FR-6 多语言（i18n）【现状】
- **界面语言与简历正文语言同源**：切换语言时，界面文案与简历正文（预览/打印/导出）同步切换。
- 支持 5 种语言：中文、English、日本語、Deutsch、한국어。
- 多语言字段须有回退机制：当前语言缺失时回退到默认语言，再回退到任意已有语言，保证缺语言也能出片。
- 正文字体须跨设备打印一致；界面须正确标注语言以适配无障碍与打印语义。

### FR-7 预览与分页（Pagination）【现状】
- **A4 精确分页**：编辑器内即渲染离散的 A4 多页，逐页对应打印。
- 统一页边距 + 底栏留白保护区（避免正文贴底）。
- 分页须满足：
  - 单条内容（如一条经历）不跨页拆开，放不下则整块移到下一页。
  - 章节标题不与首条内容分离（避免标题孤行在页尾）。
  - 编辑输入时需防抖重排，避免编辑光标丢失；字体加载完成后重新计算分页。
  - 实时显示总页数。
- 预览区自动缩放，保证整页宽度可见。
- 两种版式：单栏 / 侧栏双栏（侧栏每页重复出现）。

### FR-8 导出与打印（Export / Print）【现状】
- **一键导出 PDF 文件**（pdf-generate，默认）：把每页渲染结果截为高分辨率图片合成 PDF 直接下载，干净无系统页脚、屏幕专属元素不上纸，适合发送与 iOS 落盘。
- 预览即所得：导出内容与屏幕预览共用同一套已分页的 `.print-area`。

### FR-9 持久化与导入导出（Persistence）【现状】
- **本地优先**：内容自动保存于用户本地浏览器，刷新不丢。
- 数据须向前兼容旧版本格式，升级不丢数据、不报错。
- **导出备份**：将当前简历与外观导出为本地备份文件。
- **导入备份**：读取本地备份文件并恢复（带格式校验，失败给出明确提示）。
- 隐私承诺：无后端、无账号、无上传；关闭页面即带走，清除缓存即消失。

### FR-10 撤销 / 重做（Undo / Redo）【现状】
- 提供全局撤销/重做，含合理步数上限。
- 连续同类微小变更（如连续打字）应合并为一步，避免历史被刷屏。
- 支持快捷键（撤销 / 重做），且与界面按钮行为一致。

### FR-11 更多操作（More Menu）【现状】
- 导入 / 导出备份、填充示例、清空（清空须二次确认）、界面语言切换。
- 操作结果给出轻量提示（toast）。

## 四、非功能需求 · Non-Functional Requirements

### NFR-1 数据隐私【强约束】
- 不存储用户任何数据；纯前端运行，无后端、无账号、无上传。
- **表达禁区**：不得宣称"云端同步""多端登录""团队协作"（与本地优先冲突且未实现）。

### NFR-2 性能
- 自动保存与历史记录应解耦，避免频繁写盘阻塞编辑。
- 分页重排须防抖，编辑输入时不卡顿、光标不丢失。
- 编辑区内核应以内容为单一真源，仅当外部内容整体变化（导入/撤销/示例）时才重置，避免编辑被覆盖。

### NFR-3 安全
- 用户产生的富文本在展示前必须经过清洗，杜绝脚本注入（XSS）；仅允许安全的语义标签与强调色。
- 所有必要的底层 DOM/系统交互应集中收口，避免散落各处引发安全问题。

### NFR-4 可访问性（a11y）
- 使用语义化结构，键盘可达，关键控件有可访问名称与提示。
- 富文本编辑区应声明为多行文本输入角色。

### NFR-5 国际化
- 中/英/日/德/韩五语完整支持，界面与正文同源切换。

### NFR-6 工程约束（原则级）
- 纯前端、本地优先、无后端依赖。
- 提交前必须通过代码检查、自动化测试与构建。
- 代码风格与提交信息遵循团队约定。

## 五、内容数据范畴 · Content Scope

> 以下以自然语言描述简历应包含的信息，不限定存储结构。

- **基本信息**：姓名、职位、电话、邮箱、城市、微信、网站。
- **自我评价**：整段富文本。
- **经历类条目**（工作经历 / 项目经历 / 教育背景）：主标题、副标题、起止时间（含"至今"）、描述（富文本）。
- **专业技能**：按分组组织，每组含分类名与条目列表。
- **章节**：决定上述内容的顺序与是否显示，每个章节可自定义标题。
- **外观偏好**：版式、主色、气质、疏密。
- 所有文字类字段支持多语言版本。

## 七、重建范围与注意 · Rebuild Scope

### 7.1 重建时优先保留的核心能力
1. 内容与观感分离的信息组织方式。
2. 通用、准确的 A4 分页能力（单块不跨页、标题不孤行）。
3. 富文本清洗与安全的就地编辑体验。
4. 多语言同源切换与字段回退。
5. 撤销/重做合并步与快捷键一致。
6. 本地持久化与旧数据兼容。

### 7.2 潜在改进方向（待产品决策，非本次强约束）
- 增加更多版式/模块（如证书、语言、作品集）。
- 导出格式扩展（直接生成 PDF、图片）。
- 模板市场 / 共享（注意与"本地优先"定位权衡）。
- 多简历管理。
